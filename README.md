# Talos MCP plugins

Official MCP definitions for Talos. The first Browser integration is under development; publishing this repository does not mean the corresponding Talos release is complete.

```text
mcp/
  browser/
    talos-mcp.json
    requirements.in
    requirements.lock
    README.md
```

Add one directory under `mcp/` with a `talos-mcp.json` single-server definition. Talos discovers it through the configured Git source. No `plugin.json`, root index, custom installer or bundled third-party executable is required. Official source membership does not automatically install every entry; only the verified Browser is a default installation in the first release.

A definition uses the existing `name`, optional display metadata and `transport` fields. Use `stdio` with `command`/`args`/`env`/`cwd`, or `streamable_http` with `url`/`headers`. Pin upstream package versions in commands or a package-owned lock, never `latest`. Runtime tools such as Node/uv must already be available on the target Worker. HTTP entries connect to existing services. Keep secrets out of this repository; users configure credentials through Talos.

## Delivery contract

The corresponding Talos integration must reuse the existing Plugin lifecycle. Page and CLI management requests are dispatched by the server to the selected Worker. Desktop uses an embedded Worker; Docker uses a container Worker. Both use the same Plugin installation records, enabled state and lifecycle. Refreshing this repository discovers updates; it does not silently replace installed revisions or enable disabled plugins.

Talos release builds consume an immutable Git commit and package a source snapshot. The snapshot's `source.json` is generated by the Talos build tooling from that commit; it is not a second plugin manifest and is not stored in this repository.

## Add a plugin

Create `mcp/<name>/talos-mcp.json`, commit the definition and refresh the Git source in Talos. For an existing remote MCP service:

```json
{
  "name": "example",
  "display_name": "Example",
  "description": "An existing MCP service.",
  "transport": {
    "type": "streamable_http",
    "url": "https://mcp.example.com/mcp",
    "headers": {}
  }
}
```

For stdio, use the same manifest with a pinned upstream command and arguments. Talos starts that command on the selected Worker; the definition does not install a missing Node or Python runtime. Browser's Docker dependency lock is a product-owned exception, not an arbitrary install hook for third-party entries. Keep `default_install` and `browser` metadata out of ordinary third-party definitions.
